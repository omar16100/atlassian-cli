# Release 0.12.0 (plan)

Status: shipped in v0.12.0 (PR #171), tag `v0.12.0` on `f50e7fe`.

## Context

`## [Unreleased]` in `CHANGELOG.md` held one entry: PR #170 (comment visibility for Jira,
from contributor PR #158 by Kim Kennof, closes #157), merged after 0.11.0 shipped earlier the
same day. The owner asked for a release.

## Version choice: 0.12.0

A new user-visible capability (`--visibility-role` and `--visibility-group` on `jira issue
comments add` and `update`, plus `--visibility-public` on `update` only) and
one behaviour change a script can observe: `comments update` without a visibility flag now
performs a GET before the PUT and keeps the comment's restriction, where 0.11.0 sent only the
PUT and republished the comment. New flags and a behaviour change are a minor bump under the
project's pre-1.0 practice.

## Approach

Following `AGENTS.md` "Releasing":

1. `CHANGELOG.md`: Unreleased promoted to `## [0.12.0] - 2026-10-16` with a short paragraph,
   an empty `## [Unreleased]` above it, compare links for `[Unreleased]` and `[0.12.0]`.
2. `[workspace.package] version` in `Cargo.toml` and the five internal pins in
   `crates/cli/Cargo.toml` to 0.12.0.
3. `cargo check --workspace` to move `Cargo.lock`.
4. `make pre-commit` (`crates/cli/tests/cli_integration.rs` asserts the version).
5. `dist plan --output-format=json`: `announcement_tag` is `v0.12.0` and the GitHub body
   carries the 0.12.0 section.
6. Codex review of the diff, pull request, CI green, squash merge.
7. Tag the merge commit on `main`: `git tag -a v0.12.0 -m "Release 0.12.0"`, push the tag.
8. Verify: `gh release view v0.12.0`, four target artifacts, six crates on crates.io at
   0.12.0, Homebrew formula updated, downloaded artifact runs `--version` and the new flags
   appear in `jira issue comments update --help`.
