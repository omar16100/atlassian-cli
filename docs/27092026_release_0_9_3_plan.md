# Release 0.9.3 (plan)

Status: in progress on `release/0.9.3`.

## Context

`## [Unreleased]` in `CHANGELOG.md` held three entries, all merged to `main` on
27 Sep 2026:

- Changed: `jira bulk export`, `jira audit export` and `confluence bulk export`
  take `--export-format json|csv`; a global `--format json|csv` still picks the
  file format when `--export-format` is absent (#146).
- Fixed: those three commands panicked on every run since 0.2.5 (#146).
- Security: `openssl` 0.10.81, vendored OpenSSL 3.6.3, 8 advisories (#148).

Added at release time, from the #148 description and codex review: a Changed
entry for the system OpenSSL floor (`OPENSSL_NO_VENDOR=1` builds need 1.1.0 or
newer, `openssl-sys` 0.9.117 rejects 1.0.2), and the list of `--format` values
that fall back to JSON.

The other PRs merged since 0.9.2 carry no user-facing change and, per
`AGENTS.md`, no changelog entry: #144 (dependency bump with argon2 0.6, key
derivation unchanged, no advisory closed), #145 (README), #149 (test fixtures and
README test counts). Dependabot #147 was closed, superseded by #148.

## Version choice: 0.9.3

The changelog states Semantic Versioning. Before 1.0 this project has bumped the
patch number for releases that add a flag or fix a bug without removing anything
that worked, and the minor number for new command groups or deliberate behaviour
changes:

- Patch with a new flag: 0.3.3 (`--field` on `jira issue create`/`update`), 0.4.2
  (`--sprint`).
- Patch with fixes and security bumps: 0.4.3, 0.7.1, 0.7.2, 0.9.1, 0.9.2.
- Minor: 0.6.0 (`--profile` made global), 0.7.0 and 0.8.0 (new features), 0.9.0
  ("several commands changed behaviour in ways that will be visible in
  scripts").

0.9.3 fits the patch pattern. `--export-format` is new, but the three commands it
belongs to could not run at all in 0.9.2 (they panicked before sending a
request), so no command line that worked before stops working, and the old
`--format json|csv` spelling keeps selecting the file format. The one
compatibility change is outside the CLI: building from source against a system
OpenSSL 1.0.2 with `OPENSSL_NO_VENDOR=1` no longer works. Release binaries and default builds
vendor OpenSSL on Linux and use the Security framework on macOS. The five library
crates have no public API change since 0.9.2 (#144 changed only the private body
of `derive_key` and added tests), so 0.9.3 is also a compatible Cargo version
for anyone depending on them.

## Approach

Following `AGENTS.md` "Releasing":

1. `CHANGELOG.md`: Unreleased content promoted to `## [0.9.3] - 2026-09-27`, an
   empty `## [Unreleased]` above it, compare links for `[Unreleased]` and
   `[0.9.3]`.
2. `[workspace.package] version` in `Cargo.toml` and the five internal pins in
   `crates/cli/Cargo.toml` to 0.9.3.
3. `cargo check --workspace` to move `Cargo.lock` (six workspace entries).
4. `make pre-commit`.
5. `dist plan --output-format=json`: `announcement_tag` is `v0.9.3`, and
   `announcement_github_body` opens with the 0.9.3 Changed, Fixed and Security
   sections, followed by cargo-dist's install instructions and a table of four
   targets.
6. Pull request, green CI, squash merge.
7. `git tag -a v0.9.3 -m "Release 0.9.3"` on the merge commit, `git push origin
   v0.9.3`.

No other file pins the version: `README.md` and the docs carry no install snippet
with a version number, and `crates/cli/tests/cli_integration.rs` asserts
`CARGO_PKG_VERSION`, which follows the workspace version.

Release pipeline scope, checked before tagging: `release.yml` builds, creates
the GitHub Release and pushes the formula to `omar16100/homebrew-atlassian-cli`;
its `announce` job only checks out the repository. `publish-crates.yml` publishes to crates.io. So the publish
destinations are GitHub Releases, the Homebrew tap repository and crates.io, and
neither workflow deploys a website. (Build steps still download toolchains and
packages: `apt-get`, `brew update`, rustup.) The crate `homepage` (and so the
formula `homepage`) is `https://atlassian-cli.pages.dev`.

The plan docs for #144 and #146 now read "shipped in v0.9.3".

## Review

Codex review of the release diff: no blocker. Applied: the OpenSSL floor entry,
the `--format` fallback values, and a narrower statement of what the workflows
reach. Not applied: a Fixed entry for #144 because machine ids longer than 48
bytes now derive a key. `machine-uid` 0.6 reads `/etc/machine-id` or
`/var/lib/dbus/machine-id` on Linux (32 hex characters when valid) and
`IOPlatformUUID` on macOS (36 characters), so a valid machine id on a released
target cannot reach the old limit. Codex withdrew the finding in round 2.
