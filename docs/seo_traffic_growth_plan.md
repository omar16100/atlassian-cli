## Why the Site Ranks Poorly (Root Causes)

1. **Single page** — only `index.html` exists. Google has 1 URL to index.
2. **No backlinks** — 0 referring domains (backlinks API confirmed)
3. **Sitemap has 1 URL** — `docs/sitemap.xml` only lists the homepage
4. **No Google Search Console** — GSC is not configured for atlassiancli.com
5. **No blog/content pages** — no indexable content targeting specific queries
6. **No internal linking** structure between content
7. **No structured data** (JSON-LD) for software or organization
8. **Meta tags are generic** — not optimized for target keywords

## Codex Review (GPT-5.4) — Critical Feedback

### 1. Keyword Strategy: Partially Sound
- **Core cluster is right**: `atlassian cli`, `jira cli`, `confluence cli`, `bitbucket cli`
- **Tier 3 keywords are wrong intent**: `tools like jira`, `jira collaboration tools`, `jira roadmap tool`, `confluence source editor` are SaaS-alternative queries, not CLI-tool intent. Remove them.
- **TAM is inflated**: `jira cli`, `jira-cli`, and `jira command line` are one intent cluster, not separate pools

### 2. Content Priority is Wrong
- **Article 2 should come BEFORE Article 1** — branded product page before generic guide
- **Before any blog posts**: Publish 4 product landing pages (`/jira`, `/confluence`, `/bitbucket`, `/jsm`) + `/install` + `/bitbucket-bearer-auth`. These match SERP intent better and are closer to conversion
- **Turn existing example scripts into runbook pages** (3-5 pages) before writing net-new blog content
- Don't batch 8 posts. Do: 4 product pages → 3-5 runbooks → 1 comparison + 1 flagship tutorial

### 3. Missing Keyword Opportunities
Better-fit keywords the plan missed:
- `jira bulk transition`, `jira bulk assign`, `jira jql cli`
- `jira automation cli`, `confluence backup cli`, `confluence bulk export`
- `confluence cql search cli`, `bitbucket pr cli`, `bitbucket pipeline cli`
- `bitbucket bearer token`, `jira service management cli`, `jsm request cli`
- `service desk automation cli`
- `brew install atlassian-cli`, `cargo install atlassian-cli`

### 4. Blog-Only is Insufficient
Competitor analysis shows SERPs are won by **product pages, GitHub READMEs, marketplace pages, and YouTube** — not just blog posts. Need a mixed content model:
- Product landing pages (per Atlassian product)
- Command reference docs (generated from CLI help)
- Runbook pages (from existing `docs/examples/`)
- Release notes/changelog pages
- Comparison pages
- Short demo videos
- Blog as ONE channel, not the entire architecture

### 5. Impact Estimates are Overstated
- Plan says ~3 visits/day from search, but GA shows ~288 organic users/30 days from Google+Bing+Yahoo
- 6-month target of 5,000-8,000 organic implies near-total category ownership — unlikely on this domain age
- **More credible targets**:
  - 3 months: 250-600 Google organic visits/month
  - 6 months: 800-2,000/month
  - Upside if runbook pages and distribution channels work

### 6. Biggest Blindspots
- **Authority leakage**: Site sends docs traffic to GitHub instead of keeping authority on-domain. Cargo.toml homepage points to GitHub, not atlassiancli.com
- **Bing underweighted**: Bing is the LARGEST search source (24%) but plan focuses only on Google
- **Version mismatch**: Homepage footer says v0.2.9, workspace is 0.3.0
- **Measurement gap**: No mention of Bing Webmaster Tools

### 7. AI/LLM Strategy Too Generic
Since ChatGPT already drives 8% of traffic:
- Build pages for prompts people actually ask: install, auth, bulk transition, Confluence backup, PR automation, JSM queues
- Put precise facts near the top of each page
- Add version/last-updated timestamps
- Publish stable docs URLs (not GitHub)
- Make atlassiancli.com the source of truth
- Add `llms.txt` file
- Add release-note pages
- Add machine-readable command reference generated from CLI help

### 8. Paid Search: Not Recommended
- $13-23 CPC with no clear high-LTV conversion path = poor ROI for OSS CLI
- Same budget goes further in docs, examples, and community distribution
- Only consider small exact-match tests on branded terms after install/outbound tracking is in place

### 9. Technical SEO Gaps Missed
- **Bing Webmaster Tools** — Bing is your #1 search source
- **IndexNow** support
- Package/repo homepage links should point to atlassiancli.com (not GitHub)
- On-domain docs instead of GitHub-only
- Unique titles/H1s per product page
- `SoftwareSourceCode` + `SoftwareApplication` schema
- FAQ/HowTo/Breadcrumb structured data
- XML sitemap needs `lastmod` dates
- HTML sitemap page
- RSS feed for releases/blog
- `og:image` and Twitter card meta tags
- Custom 404 page
- Auto-updated version/date fields

### 10. Distribution Strategy Adjustments
- **Add first**: Atlassian Community and Atlassian Developer Community (audience-native)
- GitHub Releases, README, crates.io, Homebrew tap → push traffic back to on-domain pages
- Reddit and Dev.to posts should be use-case-led, not "read my blog" posts
- HN only for a substantial technical launch
- Product Hunt is low-fit for this audience — deprioritize

### Codex-Recommended Execution Order
1. Set up GSC + Bing Webmaster Tools, fix canonical/schema/sitemap, stop leaking docs authority to GitHub
2. Publish 4 product landing pages + Install + Bitbucket bearer token auth page
3. Turn existing example scripts into 3-5 runbook pages before writing net-new blog posts
4. Add release-note/changelog pages for freshness and AI citations
5. Then write 1 comparison page and 1 flagship tutorial (not 8 posts in a batch)
