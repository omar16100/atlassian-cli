# Release 0.10.0 (plan)

Status: in progress on `release/0.10.0`.

## Context

`## [Unreleased]` in `CHANGELOG.md` held the entries from PR #153 (merged to
`main` as `e1fc080` on 28 Sep 2026): the six items from a user report still open
on 0.9.3, plus the fixes found alongside them. Feature write-up:
[28092026_feedback_open_items.md](28092026_feedback_open_items.md).

## Version choice: 0.10.0

The changelog states Semantic Versioning, and before 1.0 this project bumps the
minor number for deliberate behaviour changes (0.6.0, 0.9.0; reasoning in
[27092026_release_0_9_3_plan.md](27092026_release_0_9_3_plan.md)). 0.10.0 carries
several that a script can observe:

- In table mode, the default, a command that returns a single object prints a
  `field | value` table instead of JSON.
- Pipeline JSON: `build_number` is a number, missing fields are `null` rather
  than `""`, `state` has no icon, a paused build is `PAUSED`, step triggers read
  `MANUAL`/`AUTOMATIC`.
- Pipeline exit codes: 3 for a paused build (new), 1 instead of 0 for an
  unrecognised status.

A patch release would put those in front of anyone pinning `~0.9`.

## Approach

Following `AGENTS.md` "Releasing":

1. `CHANGELOG.md`: Unreleased promoted to `## [0.10.0] - 2026-09-28` with a short
   paragraph naming the script-visible changes, an empty `## [Unreleased]` above
   it, compare links for `[Unreleased]` and `[0.10.0]`.
2. `[workspace.package] version` in `Cargo.toml` and the five internal pins in
   `crates/cli/Cargo.toml` to 0.10.0.
3. `cargo check --workspace` to move `Cargo.lock`.
4. `make pre-commit`.
5. `dist plan --output-format=json`: `announcement_tag` is `v0.10.0`, and
   `announcement_github_body` opens with the 0.10.0 section.
6. Pull request, green CI, squash merge.
7. `git tag -a v0.10.0 -m "Release 0.10.0"` on the merge commit, `git push origin
   v0.10.0`.
8. Verify: GitHub Release body, crates.io versions of the six crates, Homebrew
   tap formula.

Also in this PR: the feature and plan documents for #153 marked shipped in
v0.10.0.
