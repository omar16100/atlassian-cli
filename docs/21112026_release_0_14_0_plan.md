# Release v0.14.0

Status: the tag `v0.14.0` and the six crates on crates.io are published. The
GitHub Release, the binaries, the installer and the Homebrew formula were NOT
published: the release workflow could not run its two macOS jobs. Release
0.14.1 replaces it, see
[21112026_release_0_14_1_plan.md](21112026_release_0_14_1_plan.md).

## Context

that callers ran against releases 0.9.3 and 0.13.0, a dependency correction,

## Version

0.14.0, by Semantic Versioning for a version below 1.0: a minor version for
new commands and options, and for changes that scripts and callers of the API
crate can see.

- New: `jira user search`, `jira issue update --assignee`, `me` for the current
  user, file content in `bb commit browse`, `--unresolved`, `commit_hash`.
- Behaviour changes for scripts: no `INFO` lines on stderr, `auth login` and
  `auth logout` write to stdout, a missing Bitbucket argument is a runtime error
  with exit code 1, `--repo` with a different positional repository is an
  error, and the items that the changelog marks with **Behaviour change**.
- API crate: `RateLimitInfo::reset_at` changed its type, and `ApiError` has the
  new variant `BodyReadFailed`.

## Approach

1. Merge #190 first, then each pull request after a rebase on `main` and a
   green CI run of its head. Squash merge, the default of this repository.
2. Merge #199 with a merge commit, so the two commits of the author of #183
   stay in the history.
3. Group the `[Unreleased]` entries into one `Added`, `Changed`, `Fixed` and
   `Security` section. Each pull request added a heading of its own, and the
   merges kept all of them.
4. Remove one sentence from the #190 entry: it said that the advisory check
   ignores `chrono`. #198 removed `chrono` and the exception in this release.
5. Set the status line of each dated document of this release to
   `shipped in v0.14.0`.

## Verification

Before the merges, each pull request head had six green checks: Format Check,
Clippy Lint, Tests on Linux, Tests on macOS, Security Audit and the cargo-dist
plan.

The Security workflow failed one time on `main`, after #197: `cargo audit`
refused the lockfile ("failed to find dependency: syn 3.0.3"). #197 and #198
each changed the lockfile, and Git saw no text conflict. #200 corrected the one
line.

Not verified against a live Atlassian site by the tests of this repository:
the write commands with `--assignee`, `confluence page add-restriction`,
`confluence page remove-restriction`, and the cause of the `bb pipeline logs`
failure. The pull request of each change records what its tests cover.

Required checks: `TERM=xterm make pre-commit`, `cargo audit`,
`cargo deny check`, `dist plan --output-format=json`, and the CI and Security
workflows on the release pull request and on `main` after its merge.

## Release procedure

1. Promote the changelog to `## [0.14.0] - 2026-11-21`, leave an empty
   `## [Unreleased]`, and add the compare link.
2. Set version 0.14.0 in the root `Cargo.toml` and in the five internal
   dependency pins of `crates/cli/Cargo.toml`.
3. Run `cargo check --workspace` and `TERM=xterm make pre-commit`.
4. Run `dist plan --output-format=json` and confirm that
   `announcement_github_body` contains the 0.14.0 change notes.
5. Merge the release pull request after all CI checks pass.
6. Wait for green CI and Security runs on `main`.
7. Create the annotated `v0.14.0` tag on the merge commit and push it.
8. Verify the GitHub Release notes, the four platform archives and their
   checksum files.
9. Verify the six crates on crates.io and the Homebrew formula.

## Result

Steps 1 to 7 were done. The tag `v0.14.0` is on the merge commit `c395233` of
the release pull request #201. The workflow that publishes to crates.io
passed, and the six crates are at 0.14.0.

Step 8 and the Homebrew part of step 9 did not occur. The release workflow
ended as cancelled: GitHub cancelled the two macOS build jobs before their
first step, with the annotation "The configuration 'macos-14-arm64-us-default'
is not supported". `dist-workspace.toml` named the runner `macos-14` for the two
macOS targets. The two Linux builds passed. The jobs that make the release and
the Homebrew formula were skipped.

The pull request runs of the release workflow make the plan only, so no check
showed this before the tag. The tag was not moved, and the crates were not
yanked. #202 sets the runner to `macos-15`.
