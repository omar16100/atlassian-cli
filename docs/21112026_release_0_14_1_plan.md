# Release v0.14.1

Status: release v0.14.1. The [GitHub Release](https://github.com/omar16100/atlassian-cli/releases/tag/v0.14.1) records publication status.

## Context

Release 0.14.0 is on crates.io only. Its release workflow could not run the two
macOS build jobs, because `dist-workspace.toml` named the runner `macos-14` and
GitHub no longer runs that image. No GitHub Release, binary, installer or
Homebrew formula exists for 0.14.0. See
[21112026_release_0_14_0_plan.md](21112026_release_0_14_0_plan.md).

Pull request #202 sets the runner to `macos-15`. The owner selected a patch
release: 0.14.1 has the same code as 0.14.0, with the corrected release
workflow.

## Version

0.14.1. A patch version: no change in commands, output or the API crate. The
tag `v0.14.0` stays where it is, and the 0.14.0 crates are not yanked.

## Approach

1. Add a `## [0.14.1]` section to the changelog that says what occurred with
   0.14.0, and keep the 0.14.0 section unchanged. The section of the released
   version is the body of the GitHub Release, so it points to the 0.14.0
   section for the changes since 0.13.0.
2. Set version 0.14.1 in the workspace and in the five internal dependency pins.
3. Correct the status line of the 0.14.0 plan and add its result.

## Verification

`dist plan --output-format=json` gives the runner of each build job. No job can
use a retired image: the two macOS targets use `macos-15`, and the two Linux
targets use `ubuntu-22.04`. The other jobs of the release workflow and the
crates.io workflow use Ubuntu runners.

Not verified before the tag: a macOS build on `macos-15`. The pull request runs
of the release workflow make the plan only, so the first such build is the run
of the tag. The `x86_64-apple-darwin` target is a cross build on that runner.

Required checks: `TERM=xterm make pre-commit`, `cargo audit`,
`cargo deny check`, `dist plan --output-format=json`, and the CI and Security
workflows on the release pull request and on `main` after its merge.

## Release procedure

1. Promote the changelog and add the compare link.
2. Set version 0.14.1 in the root `Cargo.toml` and in the five internal
   dependency pins of `crates/cli/Cargo.toml`.
3. Run `cargo check --workspace` and `TERM=xterm make pre-commit`.
4. Run `dist plan --output-format=json`. Confirm that `announcement_github_body`
   has the 0.14.1 notes and that no job uses a retired runner image.
5. Merge the release pull request after all CI checks pass.
6. Wait for green CI and Security runs on `main`.
7. Create the annotated `v0.14.1` tag on the merge commit and push it.
8. Watch the release workflow and the crates.io workflow to their end. If a
   macOS job fails again, stop, and do not move the tag.
9. Verify the GitHub Release: the four platform archives with their `.sha256`
   files, the installer script and the release notes.
10. Verify the six crates at 0.14.1 on crates.io and the Homebrew formula at
    0.14.1.
